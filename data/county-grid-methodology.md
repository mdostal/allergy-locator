# County grid methodology (gradient densification layer)

**What this is.** `data/county-grid.json` scores all 3,143 US counties for
grass + the 28 comprehensive allergens, generated by `scripts/gen_county_grid.py`
from real public data (see `data/raw/README.md`). It exists for ONE reason:
the map's gradient (`src/components/HeatmapLayer.tsx`) interpolates from
sample points, and 168 cities alone left huge stretches of the country with
no nearby sample to interpolate from. This is a **secondary, coarser-
confidence layer that only feeds the gradient's spatial interpolation** — it
does not touch, override, or get shown instead of the 168 authoritative,
ground-truth-anchored cities in `data/cities.json`. Every city marker,
detail-panel breakdown, and report ranking in the app still comes from the
168-city data, unchanged.

## What's real vs. modeled here

- **County centroids, population:** real (US Census Bureau, 2020).
- **Elevation:** real (open-elevation.com, keyless public API).
- **Köppen climate zone:** NOT fetched from a real classification dataset —
  computed by a rule-based classifier (`scripts/koppen_classify.py`) using
  latitude/longitude/elevation/state, calibrated to 98.2% agreement (165/168)
  against the existing hand-curated city zones. This is a genuine
  simplification of real Köppen classification (which is fundamentally
  driven by exactly these inputs), not an arbitrary guess — but it is a
  simplification. The 3 residual misses against the calibration set (San
  Jose CA, Sundance WY, Los Alamos NM) reflect real fine-grained microclimate
  distinctions too specific to generalize, not classifier bugs.
- **Turf/irrigation exposure (grass only):** computed from real county-level
  NASS 2022 Census of Agriculture (hay + sod harvested acreage) and USGS 2015
  water-use (crop irrigation withdrawal) data — see `docs/TURF-DATA-SOURCES.md`
  for the original research spec. **Known, confirmed limitation:** this
  captures AGRICULTURAL irrigation well but cannot see URBAN/residential lawn
  irrigation, because that requires NLCD 30m land-cover raster processing
  (the "landTurf" component in `docs/TURF-DATA-SOURCES.md` §6.1), which needs
  GIS tooling and multi-GB downloads not run here. This was verified directly
  during generation, not assumed: Ada County, ID (Boise) — a real irrigated-ag
  valley — picks up a meaningful boost (64/100) from real hay-acreage + irrigation
  data, correctly moving toward Boise's own hand-tuned 88; but Salt Lake
  County, UT scores only 9/100 against Salt Lake City's hand-tuned 58,
  because Salt Lake City's real turf driver is suburban lawns, not farmland,
  and agricultural data simply doesn't see that.
- **The grass-seed-farming proxy (`GRASSES & LEGUMES TOTALS` in the 2022
  Census of Agriculture) is effectively non-functional** — that line item is
  almost universally suppressed or unreported at county level (verified: the
  95th percentile across all 3,143 counties is 0). Kept at a token 10% weight
  in case a future Census vintage populates it; the real signal comes from
  hay+sod acreage and irrigation withdrawal.
- **Coastal flag:** not computed from real coastline geometry — inherited
  from whichever of the 168 hand-curated cities is nearest, when that city is
  within ~1 degree (~70 miles); otherwise defaults to non-coastal. A cheap,
  reasonable proxy for a factor that only nudges the grass score by ±4 points.
- **The 28 comprehensive (non-grass) allergens** reuse `scripts/
  source_allergens.py`'s existing Köppen-zone-table / state-presence-gate
  logic completely unchanged — that logic was already purely zone/state-
  driven with no per-city hand-tuning, so it generalizes to any county for
  free, with no new modeling assumptions.

## Why this design is still honest and useful

IDW interpolation (`src/lib/heatmap/interpolate.ts`) weights nearer points
more heavily. Near any of the 168 cities, that city's own precise value
dominates the rendered gradient; the county grid's influence is strongest in
the large gaps between named cities, which is exactly the coverage problem it
exists to solve. Where the county model is known to understate (dense urban
metros driven by lawn irrigation rather than farmland), the nearby city point
still anchors the correct local peak — the surrounding county fill is a
reasonable, lower "regional background," not a contradiction.

## Refreshing this data

Re-run `python3 scripts/fetch_county_data.py` periodically to pull fresh
Census/USGS/NASS releases into `data/raw/`, then `python3 scripts/
gen_county_grid.py` to regenerate `data/county-grid.json`. Both scripts are
idempotent and safe to re-run; the fetch script caches elevation lookups so
re-running it doesn't re-fetch data it already has.
